# Adaptive rebuild study

The faculty workflow reads these archives and can separately run one short adaptive trial on disposable members. [Verified research commands](../../docs/DEMO_COMMANDS.md#n-benchmarks-and-figures)

**H1.** Under meaningful foreground-read load, adaptive pacing reduces scheduled-arrival-to-completion foreground p95 relative to full-speed rebuild, with a measurable rebuild-completion-time cost.

**H0.** Adaptive pacing does not produce a reproducible reduction in foreground p95 relative to full-speed. The primary comparison uses matched repetitions under the same offered read schedule. Fixed pacing and a degraded control provide separate references. Secondary outcomes are p99, IOPS, logical throughput, rebuild time and throughput, pacing overhead and progress.

The storage members are files on a shared host SSD. Measurements describe the file-backed simulator, its synchronization, and Windows caching. Dedicated physical-drive measurements require a separate hardware experiment.

## Policy, timing, and integrity

Full-speed adds zero intentional delay. Fixed throttle applies one constant pause before each subsequent reconstruction or verification batch. The adaptive controller changes this same delay only at safe boundaries. It continues to use the existing catalog and job lease for readiness, reconstruction, spare flush/readback, checkpoint publication, verification, and promotion. Processing time starts after source validation and includes the batch work and its checkpoint operation. Catalog hold time brackets the locked work through session teardown. Throttle wait is measured wall time observed around the intentional wait and can include pause checks and Windows timer wake-up latency. Rebuild elapsed time starts with the successfully saved RUNNING state and ends with the durable completion and promotion. The processing, wait, and catalog metrics overlap where applicable and are not an exhaustive elapsed-time decomposition.

Adaptive defaults observe a 250 ms window, update at most once every 80 ms, and return to a zero delay after 200 ms with no new arrival and no outstanding read. An empty window with no prior arrival also starts unpaced. Instantaneous pressure is the maximum of submitted IOPS / 80, p95 / 8 ms when available, and 1.25 when at least one read is outstanding. Pressure is smoothed with EWMA coefficients 0.65 previous and 0.35 current. High enters above 1.15 and stays high down to 1.0 with a valid latency signal. Low enters below 0.85 with a valid signal. The middle band holds the delay. A missing p95 after fewer than four successful samples holds the delay unless arrival or outstanding pressure can increase it. Non-idle adjustments are 1 ms within the configured bounds of 0–6 ms in this study.

Completed IOPS is an observation only. Actual dispatch and outstanding demand let the controller detect pressure even when completions slow. The benchmark's runner owns a single foreground worker, so reads queued in its scheduled-arrival list influence measured response but are visible to the controller only when dispatched. Process-local rings hold the newest 2,048 arrivals and 2,048 completions each. The scheduler cannot defer the next batch beyond its bounded intentional delay. Progress still depends on acquiring the Windows catalog lock, successful I/O and host scheduling. Under continued traffic every study rebuild advances to verified completion. A bounded wait is not a delivery deadline.

Each independent trial creates a fresh deterministic RAID 1 fixture of two members and a spare. A 4 MiB image has 1,024 4 KiB blocks, a one-block stripe unit, and 16-block reconstruction batches. The variable trial uses 8 MiB members with the same batch size. The runner verifies the original logical data before failing slot zero, preserves source SHA-256 digests, checks all read data, checks every reconstruction checkpoint against the exact expected block count, and verifies final member contents and mirror consistency. The degraded control reserves an eligible spare and remains DEGRADED throughout, with rebuild quantities unavailable. Foreground writes remain blocked by the existing policy.

## Calibration and comparison

The pre-matrix Release pilot used the same RAID 1 geometry with a 900 ms window. The degraded control completed **170 IOPS** with 400 scheduled IOPS. Main rates were set at **40, 85, and 145 IOPS**, approximately 24%, 50%, and 85% of that observed rate. Pilot full-speed idle rebuild finished in 1.6088085 s. Dividing by 127 possible inter-batch waits estimated a 12.7 ms fixed delay for about half the unpaced idle throughput. Windows timer delays, contention, and cache variability can shift the actual ratio. The fixed configuration was chosen once and frozen before the 75-trial comparison. The pilot used an initial 3 ms placeholder for its fixed arm.

Each main trial offers 1,300 ms of fixed-rate arrivals. Scheduled times are absolute relative to trial start. A single FIFO worker submits late requests as capacity becomes available and retains their scheduled timestamps. The runner drains after the offer closes. Foreground latency includes late starts and catalog entry through scheduled-arrival-to-completion timing. C++ service time begins after opening the array and ends when the RAID read returns. Window IOPS count successful completions before the common window closes. The active subset requires the worker to be active at dispatch and the array to be degraded at service, and separately reports completions within the active portion of the offer window. Its latency can include a completion that follows the end of that window. The experiment has no foreground warm-up requests. Fixture setup and integrity checks warm the normal host cache outside timing. All tests use the ordinary Windows filesystem and cached I/O; cache-flushing settings are untouched.

Five repetitions per cell use base seed 14024, with the deterministic Step 13 generator mixing the repetition into the address stream. Policies in a matched cell receive the same starting data, offered times, and addresses. The runner rotates load order and policy order by repetition and records that order. Sample SD is between trial values. Latency quantiles are nearest-rank per trial and then summarized across repetitions. The paired percentage is `100 × (adaptive − baseline) / baseline` for each match, with undefined results left blank. Failed or invalid trials remain in raw output and are listed in exclusions. Five matched repetitions yield descriptive evidence only.
